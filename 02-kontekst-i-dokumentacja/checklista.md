# Checklista samooceny - moduł 2

- [ ] Wiem, że rozrost kontekstu kosztuje **dwa razy**: pieniędzmi i jakością odpowiedzi. → *2.1*
- [ ] Umiem odczytać `/context` i wiem, że sekcja **Memory files** to jedyny dowód,
      że mój plik kontekstowy działa. → *2.1, lab 2.1 krok 1*
- [ ] Mam zmierzoną różnicę między czytaniem hurtowym a celowanym - na własnym repo
      albo na ćwiczeniowym. → *lab 2.1*
- [ ] Potrafię sformułować prompt tak, żeby agent sam wybrał tańszą drogę
      (mówię **co ustalić**, nie **jak czytać**). → *rozwiązanie 2.1*
- [ ] Wiem, kiedy RAG ma sens, a kiedy jest kosztownym zastępnikiem czytania plików. → *2.2*
- [ ] Umiem wskazać trzy rzeczy, których **nie** wpisuję do dokumentacji, bo model
      przeczyta je z kodu. → *2.3*
- [ ] Umiem wskazać trzy rzeczy, które **muszę** wpisać, bo z kodu ich nie widać. → *2.3*
- [ ] Znam cztery lokalizacje `CLAUDE.md` i wiem, że pliki się **sklejają**, a nie nadpisują. → *2.4*
- [ ] Wiem, dlaczego celem jest 200 linii i co robię, gdy plik rośnie
      (skill → reguła z `paths:` → dopiero potem `@import`). → *2.4*
- [ ] Wiem, że `@import` **nie oszczędza kontekstu** - porządkuje pliki. → *2.4*
- [ ] Potrafię odróżnić instrukcję sprawdzalną od życzeniowej. → *2.5, lab 2.2 krok 4*
- [ ] Wiem, że `CLAUDE.md` to kontekst, nie egzekucja - i co zrobić z regułą,
      która musi zadziałać zawsze. → *2.5*
- [ ] Wiem, że serwer MCP dostarcza modelowi tekst, który działa na niego jak instrukcja. → *2.6*
- [ ] Mój `CLAUDE.md` nie zawiera ani jednego sekretu, danych osobowych ani treści klienta. → *2.4*
