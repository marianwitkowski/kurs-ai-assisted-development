# Checklista samooceny - moduł 3

- [ ] Umiem wyjaśnić, dlaczego agent nie dopyta, tylko dopowie - i że to właściwość,
      a nie usterka do naprawienia lepszym modelem. → *3.1*
- [ ] Wiem, dlaczego błędne założenie jest groźniejsze od halucynacji. → *3.1*
- [ ] Policzyłem, ile rozstrzygnięć agent podjął za mnie przy gołym wymaganiu. → *lab 3.1 krok 1*
- [ ] Umiem wejść w tryb planowania czterema sposobami i wiem, że na Pro/Max sesja
      startuje w trybie auto, nie Manual. → *3.2*
- [ ] Wiem, że `Ctrl+G` pozwala poprawić plan ręcznie przed zatwierdzeniem. → *3.2*
- [ ] Umiem wymienić cztery elementy, których żądam od planu - i wiem, że najważniejsze
      są wypisane założenia. → *3.2*
- [ ] Znam cztery techniki przeciw dopowiadaniu i użyłem przynajmniej dwóch. → *3.3*
- [ ] Umiem napisać kryterium akceptacji jako **liczbę**, nie jako opis. → *3.3, lab 3.1*
- [ ] Wiem, że **zakres negatywny** („czego nie robimy") jest ważniejszy od pozytywnego. → *lab 3.1 krok 3*
- [ ] Moja specyfikacja miała niepustą sekcję „Otwarte pytania". → *lab 3.1*
- [ ] Napisałem testy **przed** implementacją i nie zmieniałem ich, żeby przeszły. → *lab 3.2*
- [ ] Przeczytałem diff i sprawdziłem, czy agent nie „poprawił po drodze"
      czegoś poza zakresem. → *lab 3.2 krok 3*
- [ ] Rozumiem, dlaczego najdroższe zmiany układa się na koniec. → *rozwiązanie 3.2*
- [ ] Umiem rozpoznać moment, w którym specyfikacja milczy - i wiem, że wtedy
      wybieram wariant zostawiający ślad. → *rozwiązanie 3.2*

które w nim rozstrzygnąłeś sam, bo „to oczywiste". Sprawdź, czy dla kogoś innego
były oczywiste tak samo.
